### [2026-11-07T02:10:00Z] a-router-200-proves-nothing
The local-router resolves an unknown model id through its generic `fallback-models` chain and returns HTTP 200 with a *different* model. A driver that checks only the status code silently runs on whatever the chain picked. The only durable signal is comparing `response.model` to the request, and even that needs care: the router-facing id is `openrouter-<id>` while the provider answers `deepseek/<id>`, so normalisation must strip both decorations without collapsing a snapshot suffix (`-1017` is a different model, not a formatting variant). Related and verified live: `deepseek-v4.1-flash` is a reasoning model, so `max_tokens: 16` yields empty content and 16 reasoning tokens. Empty content with a reasoning count is a budget error, never a transport failure - misreading it sends the caller to a fallback tier for a problem the next tier will reproduce.

### [2026-11-07T02:10:00Z] isolation-must-be-a-signature-not-a-comment
The Goldfish reviewer's whole value is that it sees no session state. Implementing that as "we simply don't pass the session" is a comment, and the next refactor adds a parameter for convenience. Making the function `goldfish_review(driver, task, retrieval_text, elephant_text, token_cap)` - with no session, history, memory, or comms reachable from its body - turns the claim into a shape a test can assert. Two cheaper failures found the same way: a stray edit had deleted an `elif` header, so a whole subcommand body ran unconditionally and appended a `GATE:` line to every `--json` envelope (fixed by asserting the child's stdout parses as JSON, not by eyeballing output); and a budget ladder that trims by blank-line blocks cannot bound a single oversized chunk, so any such ladder needs a final hard truncation.

### [2026-11-07T02:55:00Z] a-fallback-order-belongs-to-its-consumer
The driver order lives in `ainish-rag` (`DRIVER_CHAIN`), not in local-router's `fallback-models` chain. That chain is shared with VS Code, Claude Code, Cline and every other client on the machine, so repointing it to suit one tool reroutes everything. The useful shape is that the shared chain becomes one *step* in the consumer's own order: step 1 calls it deliberately (and is marked `expect_any`, because whatever it picks is correct for that step), while steps 2+ are pinned model ids whose mismatch is a real signal. Two facts from probing that cost time: router ids answer provider-stripped (`xiaomi-mimo-mimo-v2.6-pro` comes back as `mimo-v2.6-pro`, `zai-glm-5.3-flash` as `glm-5.3-flash`), so identity matching must be suffix-based or every pinned step reports a false mismatch; and an offline mode that filters its chain down to nothing reports "no step configured" instead of the local backend's real error, so the floor step must survive the filter.

### [2026-11-07T02:55:00Z] unattributed-is-not-the-same-as-unexplained
I found a line appended to `AGENTS.md` that I had not written, treated it as contamination, removed it and restored the file. The operator had added it. Removing content a human put in the governing contract is a worse error than shipping it, because the contract is theirs and my diff is the thing under review. The right move for unexplained human-authored content is to keep it and ask, and only strip it when it is provably machine-generated output (a tool's log line, a hook's stamp) rather than a person's edit. Attribution needs evidence, and "I don't recognise it" is not evidence.
