`--rules` silently deployed zero `.agents/skills/` packs because `b268b75` removed the interactive selector (to stop a WSL stall) and `fdd8537` then defaulted unrecorded packs to OFF — leaving no way to record a selection from the rules path. The selector's key read is now bounded by `AINISH_SKILLS_PROMPT_TIMEOUT` (default 120s) and a cancel/timeout falls back to the saved selection, so the stall that motivated the removal cannot recur through this path.

### [2026-11-05T03:20:00Z] wsl-sigttin-engine-hang-root-cause
The hang is SIGTTIN, not slowness. Under WSL the Windows `ainish-rag.exe` is launched through `/init`, which reads inherited stdin. When the caller is not in the foreground process group — a command substitution inside `--rules`, a git hook, any backgrounded job — that read raises SIGTTIN and the process enters state `T` (`wchan: do_signal_stop`) instead of failing. A stopped child also stops the `timeout` watchdog with it, so the 20s bound never fires. Proven by probe: inherited pty stdin hangs (rc=124 after 42s); the same command with `</dev/null` completes in 1s. Fixed by detaching stdin on every engine invocation (`embed_config_delegate`, `_ainish_rules_sign_manifest`, `_ainish_rules_verify_manifest_sig`, and the `audit contract` re-sign in `agents_protection.sh`), plus `stdin=subprocess.DEVNULL` on the Python fallbacks. Real-engine pty `--rules` went from indefinite hang to 6-8s exit 0.

### [2026-11-05T03:20:00Z] pqc-install-fresh-install-false-negative
`--pqc-install` reported `ok:false` on every fresh install because it required `bundleExists`, but `keygen` only creates the ML-KEM-768 keypair — `secrets.bundle.json` appears the first time a secret is packed. Existing stores masked this. Success now means "launcher installed and usable identity resolves": `_pqc_ensure_identity` reports `generated`, `present` (keypair already there, keygen exit non-zero), or `failed`, and only `failed` fails the install. The test's own assertion name ("keygen not required") confirmed the intent.
