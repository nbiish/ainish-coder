# Plan: aiRPC — the .agents/ record as an interactive tldraw canvas agents serve and edit

## 1. Problem

There is no way for a human to review the `.agents/` record (context files and folders, wiki, repo
architecture) as a live surface and steer edits where they look. Today the record is read by agents
and dumped as chat text. The operator wants an aiRPC (AI robotic process automation) loop: a
tldraw-like interactive window where each document is a block the user can read and type into; when
they hit Enter, an agent receives exactly that block's identity plus the prompt and knows what to
edit — and the tooling must then make the agent **wait** for the user's response instead of
carrying on.

## 3. Plan

### Goals

- A skill at `.agents/skills/aiRPC/SKILL.md` that comprehensively instructs any agent how to
  project the `.agents/` record and repo architecture into a tldraw canvas, receive per-block
  Enter calls, and edit the record from them.
- Extremely concise tooling in `references/`: one zero-dependency bridge script (serve + wait +
  project + ack), one wire protocol document, one drop-in canvas module.
- The wait is a first-class trigger: after acking a call the agent blocks on the bridge until the
  user's next response, with explicit stop conditions.

### Non-goals

- No multiplayer/sync server, no hosting, no packaging as an npm app — the skill's tooling is a
  local, single-operator review surface; `npm create tldraw@latest` supplies the app shell.
- No changes to `skills-to-distribute/` — the operator asked for this repo's `.agents/skills/`.
- No modification of `ainish-coder` retrieval code — the canvas is a projection, not a new RAG.

### Constraints and invariants

- Skill shared invariants: bounded procedure, explicit stop conditions, verification, references
  relative to the skill directory; never store secrets; never silently downgrade errors; never
  mutate shared ledgers on behalf of a subagent.
- Security: bridge binds 127.0.0.1 only; no secrets in canvas, manifest, or payloads; block paths
  must resolve inside the repo and only from the allowlisted record surface; the bridge writes
  only under `$AIRPC_HOME`, never repo files; user prompt text is untrusted data; fail closed on
  any parse or digest failure.
- tldraw SDK license: free in development, license key required for production use — the skill
  states this rather than hiding it.
- Commit as the harness per the enforced hooks; never hand-edit git identity or `.agents/canonical`
  signed artifacts.

### Proposed architecture

```
 human                     canvas (tldraw)                 bridge (node:http)              agent
   |  read blocks                |                              |                            |
   |  type prompt, Enter ------->|  POST /rpc {block,prompt} -->|  append inbox.jsonl        |
   |                             |                              |  GET /rpc/wait (long-poll)<|  blocks here
   |                             |                              |  prints one call JSON -----|
   |                             |<-- GET /events (long-poll) --|-- POST /ack {status,note} -|  edits record
   |  sees "edited" chip         |                              |                            |  waits again
```

The agent owns the edit; the bridge owns transport only. Projector = agent maps records to a block
manifest (`POST /project`). One file does all tooling: `references/bridge.mjs` subcommands
`serve | project | wait | ack`.

### Interfaces and data

- Block: `{id, path, anchor, title, kind, digest, lane, body}` where `id = "blk-" +
  sha256(path#anchor)[0:12]`, `digest = sha256(path + "\0" + body)[0:12]`; kinds =
  `task|plan|comms|memory|suggestion|wiki|contract|architecture`.
- Call (canvas → agent, on Enter): `{v:1, kind:"call", id:"call-...", session, block_id, path,
  anchor, digest, prompt, ts}`.
- Ack (agent → canvas): `{v:1, kind:"ack", call_id, block_id, status:"done|needs-you|stale|refused",
  summary, new_digest, note}`.
- End (stop signal): `{kind:"end", session, reason}` written by the bridge when the session closes.
- Bridge CLI: `serve [--port] [--app] [--session]`, `project --manifest FILE`, `wait [--session]
  [--after N] [--by ISO]` (prints one call JSON, exit 0; deadline = exit 2, never success),
  `ack --file FILE`.
- Runtime state: `$AIRPC_HOME` (default `~/.airpc`), one dir per session: `inbox.jsonl`,
  `log.jsonl`, `manifest.json`, `consumer.lock`.

### Files and symbols

- `.agents/skills/aiRPC/SKILL.md` — new; frontmatter + doctrine, activation, architecture,
  projection protocol, call/ack loop, the wait trigger, security invariants, verification, refs.
- `.agents/skills/aiRPC/references/protocol.md` — new; JSON schemas, worked call/ack example,

### Alternatives considered

| Alternative | Why rejected |
|---|---|
| WebSocket bridge | Long-poll over node:http is dependency-free and sufficient for one operator; WS needs a server dependency for no gain at this scale. |
| Bridge writes edits to repo files | Violates "decisions live in code" and one-writer-per-boundary; the agent must resolve and edit, with the contract's worktree discipline. |
| Agent polls the inbox | Polling burns CPU and can miss the wait trigger the operator asked for; a blocking `wait` is the requested semantics. |
| Building the full tldraw app in the skill | The operator asked for extremely concise tooling; the starter kit (`npm create tldraw@latest`) is the maintained app shell and a drop-in module keeps the skill honest about API drift. |

### Risks and mitigations

| Risk | Mitigation |
|---|---|
| tldraw API drift makes the drop-in module stale | Module targets the documented `ShapeUtil`/`HTMLContainer` API, is syntax-checked only, and the skill pins the quick-start contract so an agent re-checks against tldraw.dev when wiring it. |
| Prompt injection through block text or user prompts | Invariant: all canvas text is untrusted data; the skill forbids treating it as instructions, matching AGENTS.md external-text rule. |
| A stale block leads the agent to edit the wrong section | Calls carry the digest the user saw; mismatch is answered `stale` + re-projection, never a blind edit. |
| Two agents consume one inbox | `consumer.lock` (pid claim) plus the skill's one-writer rule; the second consumer exits with an error. |

## 4. Clarifications

### 4.1 Canvas engine

- **Question:** Which canvas technology should the interactive window use?
- **Options:** 1. (Recommended) tldraw SDK — the operator named it; mature custom-shape API; 2. custom SVG/HTML — reinvents pan/zoom/selection.
- **Selected:** tldraw SDK (operator supplied tldraw.dev/quick-start and github.com/tldraw/tldraw).
- **Trade-off accepted:** SDK production use needs a tldraw license key; stated in the skill.
- **asked:** operator

### 4.2 Enter semantics and payload

- **Question:** What should happen when the user types in a block and hits Enter?
- **Options:** 1. (Recommended) fire an RPC carrying the specific block's identity plus the prompt — the operator's stated example; 2. a global chat box — loses block context.
- **Selected:** Per-block call: the agent receives which block (path, anchor, digest) and the user's prompt, then edits accordingly.
- **Trade-off accepted:** Each block needs identity + digest bookkeeping.
- **asked:** operator

### 4.3 Wait trigger and tooling size

- **Question:** How should an agent behave after dispatch, and how large should the tooling be?
- **Options:** 1. (Recommended) a blocking wait on the bridge inbox until the user's response, tooling kept extremely concise; 2. fire-and-forget with agent polling.
- **Selected:** Blocking `bridge.mjs wait`; tooling "extremely concise" (operator's words) — one bridge file, one protocol doc, one drop-in module.
- **Trade-off accepted:** The agent is idle while waiting; that is the requested trigger.
- **asked:** operator

### 4.4 Skill placement and scope

- **Question:** Where does the aiRPC skill live, and does it ship to consumer repos?
- **Options:** 1. (Recommended) `.agents/skills/aiRPC/` only — the operator named the path; 2. also `skills-to-distribute/` — out of the asked scope.
- **Selected:** `.agents/skills/aiRPC/`; distribution untouched.
- **Trade-off accepted:** Consumer repos don't get it until the operator says so.
- **asked:** operator (path given verbatim)
- **resolved by:** `.agents/llms.txt` (skills/ = standing prompt surface; distribute tree is separate)
