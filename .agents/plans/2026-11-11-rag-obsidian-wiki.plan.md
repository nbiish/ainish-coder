# Plan: Make the RAG wiki an Obsidian-native vault, gated by decisions and a plan-first contract

## 1. Problem

The RAG engine writes six fixed markdown pages into `.agents/wiki/`. They are readable but not a
*vault*: no frontmatter, no `[[wikilinks]]`, no tags, no aliases, no per-section pages. Obsidian
therefore renders them as six orphan files with no graph, no backlinks, and no search facets — and an
agent gets the same static dump regardless of what the task needs. Separately, work in this repository
starts without a written plan, so scope and verification are improvised rather than checked against
something agreed in advance.

## 2. Anchor Facts

- The wiki is generated by two engines that must stay in step: `src/rag/src/wiki.rs` (`WikiGenerator`,
  six `render_*` fns, `generate_all`) and Python's `src/rag/rag.py` (`.agents/wiki` paths at ~2393,
  2406, 2442, 2482, 2502, 2687) — established from `grep -n "fn render_\|wiki_dir" src/rag/`.
- Current output has no YAML frontmatter, no `[[` links, and no `tags:` — established by reading all six
  pages in `.agents/wiki/` and `render_index`/`render_architecture` in `wiki.rs`.
- `ledger.md` is operator-owned and **must not** be regenerated: the generator splices it into page 04
  and the ledger is ML-DSA-65 signed (`ledger.sig`) — established from `wiki.rs:1036,2109,2636` and
  `.agents/wiki/ledger.md`.
- Retrieval is graph-first already: `.agents/rag/wiki-graph.json`, nodes are `## ` sections, edges are
  markdown links and shared vocabulary — established from `llms.txt:300`.
- **Edge extraction matches only `(path.md)` and never `[[wikilinks]]`.** `build_wiki_graph` in
  `rag.py:5026` uses `re.findall(r"\(([^)\s]+\.(?:md|txt))\)", ...)`. Emitting Obsidian wikilinks
  without teaching the parser about them would silently delete every explicit edge, leaving only the
  weaker `shared terms >= 3` edges — established by reading `rag.py:5026-5033`.
- The graph promotes only files matching `*.md`/`*.txt` next to pages, and every `## ` heading becomes
  a node, so a new `## Related` section would itself become a retrieval node unless excluded —
  established from `_graph_sources` (`rag.py:4955`) and the section loop at `rag.py:5000`.
- `local-router` is live on `127.0.0.1:11434` with 191 models — established from
  `curl /v1/models`.
- Only **two** decisions-capable models exist: `openrouter/jev-1.14`, `zenmux/jev-1.14` — established
  from the same probe (`capabilities.decisions == true`).
- **Both decision providers are currently unauthorized.** A well-formed decisions request returns
  `401 "User not found"` (OpenRouter) and `403 payg` (ZenMux). Keys exist in PQC as
  `LOCALROUTER_OPENROUTER_API_KEY` / `LOCALROUTER_ZENMUX_API_KEY` but are rejected — established from
  `curl -X POST /v1/decisions` and `pqc-secrets list`.
- **Chat fails over correctly**: requesting `zenmux-deepseek-v4.1-flash` returned `mimo-v2.6-pro`, so
  the `fallback-models` chain works for chat and not for decisions — established from that probe.
- `AGENTS.md` is 118 of a hard 120-line gate and is deployed verbatim to consumer repos — established
  from `wc -l AGENTS.md` and `scripts/test-pqc-dist.sh:623`.

## 3. Plan

### 3.1 Obsidian-native page model (`wiki.rs`, mirrored in `rag.py`)

Every generated page gains YAML frontmatter and true wikilinks:

```yaml
---
title: System Architecture
aliases: [architecture, arch]
tags: [ainish/wiki/architecture, ainish/generated]
up: "[[README]]"
generated: 2026-11-11T00:00:00Z
source_commit: <short sha>
---
```

- `[[README]]` replaces `[text](README.md)` so Obsidian builds the graph and backlinks pane.
- Each page gains `## Related` with `[[...]]` to its siblings. **This is only safe together with 3.3**:
  today's parser would not see those edges, and the `## Related` heading would become its own node.
- A `.obsidian/` config directory is written **once** (never overwritten) with a vault name and
  `attachmentFolderPath`, so opening `.agents/wiki/` as a vault works immediately.
- `ledger.md` and `ledger.sig` stay untouched by generation.

### 3.2 Teach the graph builder the wikilink syntax (prerequisite, not optional)

Before any page changes shape, `build_wiki_graph` must understand what it will be given:

- Edge extraction gains a second pattern for `[[target]]` / `[[target|alias]]`, normalized against the
  page stem, in addition to the existing `(path.md)` form. Keeping both means old and new pages coexist.
- The section loop skips navigation-only headings (`Related`, `Backlinks`) so a cross-link block does
  not become a retrievable node — it is a graph edge, not content.
- A gate asserts edge count does not regress when the format flips: generate the vault, parse it, and
  require explicit `[[...]]` edges to be present. Without this the vault looks right in Obsidian while
  `--context` quietly returns worse results.

### 3.3 Decision-driven salience (degradation-safe by design)

New: `wiki_plan` step before rendering. One typed decisions batch asks, per candidate section:

- `noul` — "Does this section carry information an agent cannot cheaply recover by reading the file?"
- `score` — importance 1–5, ordering pages within the index.

**The decision result is advisory, never load-bearing.** Because both providers currently 401/403,
the pipeline must produce a complete vault with zero decisions available. Concretely:

- Decisions resolve → sections are ranked and low-salience sections are dropped from the index.
- Decisions unavailable (401/403/timeout/absent) → **deterministic structural ranking** (entrypoints,
  file counts, symbol density, debt volume) generates the identical page set, and the page gains
  `decision_source: structural-fallback` plus a `warnings:` frontmatter key.
- The gate **never** fails open. If `--decisions required` is passed explicitly, absence is a hard
  error, because a wiki that silently looks decision-ranked when it is not is worse than a slow one.

### 3.4 Decision transport through local-router

`DecisionEngine` targets `OPENROUTER_DECISIONS_URL` directly today. Add local-router as the **first**
transport (`/v1/decisions`), then direct OpenRouter, then direct ZenMux, reusing the existing
`transport_priority_order()`. Each probe is short-timeout and classified:
`ok | unauthorized | unreachable`, so a 401 is reported as *unauthorized* (an operator action),
never conflated with *unreachable* (a transient fault).

### 3.5 Plan-first contract (hard gate)

- `AGENTS.md` gains the rule in ~2 lines by folding it into non-negotiable #1 rather than adding a
  section: no branch is cut until a plan exists in `.agents/plans/`, and the branch is verified then
  merged, not left dangling.
- Enforcement in code, not prose: a `ainish-coder --plan-check` verb plus a pre-commit hook that
  refuses a commit on a non-`main` branch whose plan file is absent or whose `status:` is still
  `designing`. The hook is additive and bypassable only with `AINISH_SKIP_PLAN_CHECK=1` logged in
  COMMS, so the refusal is auditable rather than silent.
- `scripts/test-pqc-dist.sh` asserts both: the contract line exists, and `--plan-check` exits non-zero
  without a plan and zero with one.

### 3.6 Non-goals

- Replacing LanceDB as the vector store (decision: format-only).
- Generating one page per source file; the vault stays the same six domain pages plus the index.
- Retiring the Python generator. Both engines keep producing identical page sets, guarded by a gate.

## 7. Risks

- **Decision providers are down.** Accepted: this is why 3.4 makes salience advisory. Do not treat a
  401 as a green decision signal.
- **`AGENTS.md` line budget.** Two lines of headroom; folding into #1 rather than adding a section.
  If it overflows, the change is rejected by the existing ≤120 gate, not by review.
- **Two-engine divergence.** `wiki.rs` and `rag.py` both render the wiki; a parity gate is required or
  the two will drift (this has already happened once for pack references).
- **`[[wikilinks]]` vs the existing graph builder.** CONFIRMED, not theoretical: the parser matches only
  `(path.md)`. 3.3 is therefore a prerequisite, sequenced before any page changes shape.
