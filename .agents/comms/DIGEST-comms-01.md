## Insights

From `2026-11-17-team.md`:
- Documentation in the wrong place is indistinguishable from no documentation: the federation capability was fully documented in `ainish-coder --help` (25 mentions) and the README yet invisible on the two surfaces an agent actually reads (`ainish-rag --help` 0 mentions, `AGENTS.md` 0). Record hygiene is part of discoverability too — the context injection was reporting a merged task as `implementing`, which would have made the next agent pick up finished work.
- A self-measuring acceptance gate is circular: knob-to-signal pairs correlated at rho >= 0.9 (one at 1.000) meant a gate on those signals would approve every widening of the retrieval window and report it as progress. The rebuilt gate judges against an external referent (commit-subject vocabulary) and refuses when none exists.
- Run the cheap experiment first: Phase 0 found the circularity before ~800 lines landed. Corollaries: comparing means conflates task difficulty with profile quality (use a paired test), and a probe set with self-retrieval in it is confounded.
- `pi --no-tools` makes a file-pointer evidence pattern useless — the improver replied "I'll start by reading the evidence files" and stopped, three times, until the evidence moved inline.
- A malformed model reply must not be read as KEEP_BASE; those are different facts and only one is good news. Fail closed on unparseable output.
- Test assertions anchored on a hardcoded line range broke when a paragraph was added above them — re-anchored on content. Same bug class the federation discoverability task was itself about.
- Research findings that shaped the build: the paper's Figure 7 shows refining a harness WITHOUT a reference execution and a library is a regression (Code 73.4 → 63.2), so a frozen generation-0 baseline is a hard prerequisite; and a recursive harness matching a frozen three-tool harness exactly in round 1 lost 100% of its savings to self-bloat by task 5, so KEEP_BASE must be a first-class outcome and growth capped in code. Skills are the CHEAP form because they are on-demand — the bloat vector is always-on text.

From `2026-11-18-team.md`:
- Routing can return `skip_retrieval`, producing a prime with zero mention of the contract; guarantees belong in `orientation`, which routing cannot skip. Corollary: a background learning pass must require retrieved evidence — the first real pass spawned for a route-skipped task and recorded "no corpus hit"; spawning a session to conclude nothing is the quiet waste the design exists to avoid.
- Widening a corpus can make retrieval WORSE before it helps: a global recency rank gave the 197-node research tree mean recency 0.748 against the wiki's 0.416, so research won 5 of 7 probes about unrelated subjects; fixed by ranking recency within each kind and blending 75/25 with the global rank. Also, heading-split nodes had been stamped `kind: wiki` regardless of source, making contract nodes indistinguishable from wiki pages.
- Stopword lists do not transfer from code to prose: "does"/"require"/"before" barely appear in code but are common, useless and harmful in prose — they pushed the AGENTS.md section answering "before cutting a branch" out of the top ten.
- `.gitignore` negation must negate the root DIRECTORY (`!/.agents/wiki/`), not a child pattern (`!/**/.agents/wiki/`), or git never descends and every learned page is silently swallowed.
- Measure answerability, not label agreement: "is the top hit the kind I expected" measures the evaluator's labels; "is the literal fact needed to answer present in the retrieved text" measures retrieval. Relatedly, an over-broad acceptance-marker guard rejected two correct pseudo-skills for ordinary uses of the word "acceptance" — narrow guards to the actual signal names.
- Force-push does not un-leak on a public repo: GitHub keeps unreachable objects fetchable by SHA until Support GCs them. And a leaked seed that does not derive the committed trust anchor (`5b465fa1` vs `d98405ea`) means past receipts are not forgeable — check the derivation, not just the leak.
- A gate that cannot read its input must FAIL: the audit gate's "tool-error → warn and pass" branch was the actual bug (nobody investigates a warning), and an inline heredoc in a YAML `run:` block is an IndentationError waiting to happen — move the logic to a script file and fail closed (`.github/scripts/check_cargo_audit.py`, exit 2 when undeterminable).
- A checker that stops parsing its upstream data reports whatever suits it: cargo-audit 0.21.2 could not parse the RustSec DB since at least 2026-11-16 (RUSTSEC-2026-0480 and -0211, both malformed TOML), so every failure since was the tool and every success under the fail-open logic was it checking nothing.
- The identity guard listed only third-party harness names, so our own tool's authorship passed through six merges unnoticed; and its amend omitted `-S`, so the "fix" produced unsigned commits. Include your own harness in the denylist and sign on amend.
- Deploy sweeps are deletion hazards for learned artifacts: `src/deploy_skills.sh:181` sweeps target skill dirs absent from source only when a selection entry exists, so a learned pack would survive by accident until it silently did not — hence `_skill_learned` shipped beside `_skill_mandatory` before the feature.
