## Insights

- A chain can look correct by name and be wrong by transport: the old driver steps 2–4 named the right vendors while routing every call through the local router, so one router outage failed all three at once. Pinning the `(transport, id)` pairing — not the id list — is what makes that regression impossible (source: `2026-11-14-team.md`).
- "Fresh reviewer context" and "distinct reviewer model" are different requirements; `--no-session` already guarantees the structural one, and enforcing the strict version pushed work onto a paid endpoint for a guarantee the spec never asked for (source: `2026-11-14-team.md`).
- A route cannot be verified by its request — capturing `responseModel` is what turns "reviewed by the router" into something checkable (source: `2026-11-14-team.md`).
- An intermittent blank response is indistinguishable from a model with nothing to say unless you retry and count; `attempts_made` is now reported (source: `2026-11-14-team.md`).
- pi's per-call overhead is its agentic system prompt (6,904 input tokens for a one-word reply at `--thinking high`, 56 at `off`), so thinking level — not prompt trimming — is the cost lever (source: `2026-11-14-team.md`).
- Attaching real files changes review quality: with the whole vault page available the reviewer reasoned about provenance instead of repeating an excerpt. Feeding a reviewer a whole note is cheaper than arguing with its truncation complaint (source: `2026-11-14-team.md`).
- "Which engine answers this command" was a fact the repo never wrote down: `bin/ainish-rag` forces `context`/`secrets` to Python and no native binary ships in `bin/`, so a plan scoped to `src/rag/src/` lands in code that never answers a request — proven only by the context call's own warning strings existing solely in `rag.py` (source: `2026-11-12-team.txt`).
- A generator that overwrites curated artifacts must fail closed; the old `ainish-rag wiki` read as success in both exit code and log while destroying a vault (source: `2026-11-12-team.txt`).
- A "mandatory" list duplicated for hiding is worse than no list: the copy in `_skill_channel_excluded` would have made a pack mandatory in distribution and selectable in the UI, and the other copy had already drifted without anyone noticing. One predicate, every surface asks it (source: `2026-11-12-team.txt`).
- Editing AGENTS.md is not a one-line change: the deploy path re-signs four `.agents/canonical/*` files and appends a `contract-history.jsonl` entry, so contract edits belong with the anchor rotation that re-signs the set in one pass (source: `2026-11-12-team.txt`).
- Mandatory deployment fixes distribution, not readership: a trigger-loaded pack cannot carry an always-on posture; only the contract itself fixes readership (source: `2026-11-12-team.txt`).
- A signed artifact that churns on identical content proves nothing about that content: `ledger.sig` was re-signed on every `wiki` run (same sha256, new `signed_at`, different key fingerprint) until signing was skipped when the existing envelope still verifies (source: `2026-11-11-team.txt`).
- Dropping a filename suffix turns every suffix filter into a filter that matches nothing, and matching nothing reads as "no plan of record" rather than an error — the plan gate would have blocked every new-scheme branch, including the one making the change (source: `2026-11-12-team.txt`).
- "Newest wins" implemented as newest-by-filename disagrees with mtime under grandfathering, silently and exactly on cutover days; it had to become mtime in one shared helper (source: `2026-11-12-team.txt`).
- Documentation describing a retired path as "a fallback" is itself the hazard: it made a dead embedding path look supported and hid that the controlling flag could not be set (source: `2026-11-12-team.txt`).
- `--ours` on a comms-ledger conflict would have deleted 10 real work records, because the other side was a freshly deployed template with zero entries; the correct resolution is "keep the side with entries" (source: `2026-11-14-team.md`).
- A deployed artifact masquerading as authored content is the most dangerous kind of conflict: the Windows `AGENTS.md` was a generated 177-line universal contract, and letting it govern would have made the deployment system and the repository permanently disagree (source: `2026-11-14-team.md`).
- The premise "Windows is the most updated" was false: origin held 45 commits/132 files, Windows 12/69, the Mac 4/61 — and the three held *complementary* work (Windows the Gumroad `src/*.ts`, origin the portfolio assets, the Mac the income ledger), which is why a ref sync could never have converged them and only a history merge could (source: `2026-11-14-team.md`).
- `%(refname:lstrip=N)` counts slash components, not characters — materialisation reported success while creating nothing, caught only because the gate asserted the branch existed rather than that the command exited 0 (source: `2026-11-14-team.md`).
- `launchctl bootstrap` can return 0 while the job never loads, and separately the job can load but be unable to read its own repos; verify the agent state AND the first cycle's log (source: `2026-11-14-team.md`).
- A watcher must write its change fingerprint on success only: writing it on a FAILED cycle marked the save "handled" and never retried — a silent data-loss path that would look like a working watcher forever (source: `2026-11-14-team.md`).
- macOS TCC (Transparency, Consent, and Control) is attributed per-process: terminal Full Disk Access cannot reach a launchd agent, copying `/bin/bash` elsewhere is SIGKILLed (exit 137), and the FDA picker will not navigate to `/bin/bash` — advice the operator cannot follow is not a fix (source: `2026-11-14-team.md`).
- macOS bash 3.2 has no associative arrays (`local: -A: invalid option`), so the sync scripts use parallel arrays to stay portable to the macOS/Linux/Windows targets they actually ship to (source: `2026-11-14-team.md`).
- "Synced" and "workable" are different states: a machine can hold every commit as remote-tracking refs and still have only `main` as a checkout-able branch (source: `2026-11-14-team.md`).
- Squashing `wip` commits on push would be actively harmful: `merge-base --is-ancestor` decides every fast-forward and `--latest` attributes branches by SHA, so rewriting a delivered commit leaves each peer holding a tip absent from its own history (source: `2026-11-15-team.md`).
- Fixing an installer's recorded CLI path changes live behaviour before the merge (the daemon switches to the main checkout's code immediately), so a test of the new behaviour cannot pass until merge — the correct ordering (source: `2026-11-15-team.md`).
- The test suite's `jget` helper used `\|` alternation, unsupported by BSD sed, so every boolean/scalar assertion silently read empty on macOS — 16 "failures" were the gate, not the code (source: `2026-11-11-team.txt`).
- A gate that has never been green hides pre-existing failures: machine-sync's six exit-255 failures predated the task and were masked by nobody running it (source: `2026-11-14-team.md`).
- A deployed AGENTS.md is `uchg`-locked by design: cleanup must `chflags nouchg` first, and pruning a worktree record before deleting the directory orphans it — `git worktree prune` then a literal-path removal (source: `2026-11-12-team.txt`).
- `git branch -d` is the right instrument for cleanup precisely because it refuses unmerged work — that is how `feat/agents-context-prime` survived six unrelated deletions (source: `2026-11-12-team.txt`).
