# Task Record — 2026-10-28: Native Windows support for the ainish-coder tooling

- branch: fix/windows-ainish-coder-shim
- lane: now
- scope: bin/ainish-coder, bin/ainish-coder.cmd, bin/ainish-rag.cmd, src/runtime.sh, scripts/ainish-setup.ps1, README.md, bin/README.md, llms.txt
- status: merged
- objective: Make `ainish-coder` (and the sibling tooling) runnable on native Windows — cmd.exe, PowerShell, Windows Terminal — instead of requiring Linux, macOS, or WSL. Operator repro: from `D:\Code\system-care-and-updates`, `ainish-coder --rules` returned `'ainish-coder' is not recognized as an internal or external command`.

## Root causes (each reproduced before fixing)

1. **No Windows launcher.** `bin/ainish-coder` is POSIX shell with no `.cmd` shim, so cmd.exe/PowerShell had no resolvable entry point. `bin/ainish-rag.cmd` existed, which masked the gap by making RAG look "supported" on Windows.
2. **No Windows PATH install.** `scripts/ainish-setup.sh` only edits `~/.zshrc` / `~/.bashrc`, which cmd.exe never reads.
3. **Windows path arguments unparseable.** `D:\project`, `D:/project`, `\\server\share`, and `.\child` failed the `[[ "$1" = /* ]]` absolute-path test in `src/paths.sh`, so targets were mis-resolved.
4. **`python3` resolved to the Microsoft Store alias.** On this host `where python` returns the 0-byte `WindowsApps\python.exe` App Execution Alias, which prints a Store message and exits non-zero, while real Python 3.12 sits unlinked at `%LOCALAPPDATA%\Programs\Python\Python312`. Every JSON-backed helper (`skills_selection.sh`, `agents_protection.sh`, `deploy_local_security.sh`, `verify_skills.sh`) silently failed, so skill selection never persisted.
5. **`ainish-rag.cmd` masked exit codes.** `native & exit /b %ERRORLEVEL%` inside an `if (...)` block expands `%ERRORLEVEL%` at parse time, reporting a stale status. Proven: old shim returned **0** for a failing command; new shim returns **2**. That silently greens `ainish-rag gate`.

## Deliverables

- `bin/ainish-coder.cmd` (new) — native launcher. Probes Git for Windows / Chocolatey / Scoop / MSYS2 / Cygwin install paths, then PATH `bash` while rejecting the WindowsApps WSL alias and any 0-byte candidate; forwards argv verbatim with `%*`; propagates the real exit code; exits 127 with `winget install --id Git.Git -e` guidance when no bash exists.
- `src/runtime.sh` (new) — Windows bridge shared by every entry point: `ainish_posix_path` (drive-letter, UNC, and relative backslash paths), `ainish_python` (proves an interpreter by executing it, falling back to `py -3`'s `sys.executable` and versioned installs), `ainish_install_python_shim` (shadows the broken `python3` name so existing call sites work untouched). Inert on Linux/macOS/WSL.
- `bin/ainish-coder` — sources the bridge, installs the interpreter shim, and normalises Windows path arguments before `main` runs.
- `scripts/ainish-setup.ps1` (new) — user-scoped PATH installer (`HKCU\Environment`, no elevation), idempotent, preserves the original registry value kind, appends with its own separator so `-Uninstall` is a byte-exact inverse, plus a post-install `--help` smoke test.
- `bin/ainish-rag.cmd` — rewritten to exit through labels (real exit codes) and to prove each interpreter before use.
- Docs: `README.md` platforms/installation, `bin/README.md` structure + Windows usage, `llms.txt` platform parity + a new repo-local `Native Windows Runtime` contract section.

## Verification (actual runs, not claims)

- `ainish-coder --help` — cmd.exe, PowerShell, correct banner.
- `ainish-coder --rules` — cwd-relative, absolute Windows path with spaces, and relative `.\child`: `AGENTS.md` + 22 `.agents/skills` entries deployed each time.
- Exit codes: unknown command → 1; `--rules` → 2 (pre-existing, reproduced at `HEAD` before any change); no-bash degradation → 127 with guidance.
- `ainish-rag` → 2 on a failing command (old shim: 0).
- PATH installer: install → uninstall byte-identical (1304/1304 chars), plus mid-path, only-entry, and empty-PATH cases all exact.
- `bash -n` clean on `bin/ainish-coder`, `bin/ainish-rag`, `src/runtime.sh`; simulated `uname=Linux` confirms no shim and no path rewriting off Windows.

## Known pre-existing issue (out of scope, recorded)

`ainish-coder --rules` exits **2** after a fully successful deploy, and this reproduces unchanged at `HEAD` (pre-change), so it is not a Windows regression. Also `-y` / `--yes` does not suppress the skills-selection TUI when stdin is a console (`src/skills_selection.sh:274` gates only on `-t 0/-t 1/-t 2`), contradicting the documented "skip all prompts" contract. Both are platform-independent and belong to a separate task.
