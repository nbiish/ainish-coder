## Scope

The eight repositories that already ran the tooling were registered only in the legacy
`~/.config/ainish-coder/rules-targets.json`, so `ainish-coder --rules-status` reported
"none registered" and `--rules-sync --all` (the root post-commit/post-merge hook) had
nothing to do. The legacy `sync-rules-targets.sh` hook was still the only path that
refreshed targets, and it distributes `AGENTS.md` only.

## Result

- `src/deploy_rules_sync.sh`: legacy registry importer (idempotent, drops dead and temp
  paths, dedupes, skips the source repo); `--rules-sync --all` enrolls refresher-less
  targets instead of skipping them; `--rules-doctor` understands nested targets; the
  launcher resolves through `REPO_DIR/bin`; per-target failures no longer abort the fleet.
- `src/deploy_agents.sh`: snapshots a target's `AGENTS.md` before overwrite.
- `src/file_operations.sh` + `src/deploy_gitignore.sh` + `src/deploy_agents_comms.sh`:
  scratch files are created beside their destination, so the rename stays on one
  filesystem (macOS `mv` fails cross-device with EXDEV on `/Volumes/...` targets).
- `llms.txt`: documents migration, in-place enrollment, nested-target hook policy, and
  the AGENTS.md snapshot path.
