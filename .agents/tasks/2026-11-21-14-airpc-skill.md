## What changed

| Was | Now |
|---|---|
| the record was read by agents and dumped as chat text | `.agents/skills/aiRPC/` projects it as a tldraw canvas of blocks with per-block prompt inputs |
| no way to point at a doc and say "change this" | Enter on a block fires a call carrying `block_id`, `path`, `anchor`, `digest`, `prompt` |
| no wait trigger | `bridge.mjs wait` blocks the agent between calls; deadline `--by` exits 2 (never success) |
| no relay back | ack (`done / needs-you / stale / refused`) paints status chip, summary, and note on the block |

## Findings

1. Two behavioral gaps were caught by reading the flow before the smoke, and both were real:
   `/rpc/wait` re-delivered acked calls (the protocol says unacked), and a client-side `--by`
   abort exited 1 as "bridge unreachable" instead of the deadline's exit 2. Both fixed and
   covered by the smoke.
2. The digest binding earns its keep: a call carries the digest of the text the user actually
   reviewed, so an edit never lands against a section that moved underneath them (`stale` +
   re-project instead).
3. tldraw's SDK is free in development but needs a license key in production; the skill states
   this rather than hiding it (tldraw.dev/pricing).
