## Operator-reported problem (root-caused)

`llama.exe serve` was resident at **9,657 MB RSS**. Diagnosis: `src/rag/src/server.rs` hardcoded
`--ctx-size 8192 --batch-size 8192 --ubatch-size 8192` regardless of `--max-mem`; `check_memory_cap()`
only *warned* about the cap and never influenced allocation, so the documented 2048 MB default budget was
never applied. The Python engine (`src/rag/rag.py`) had the identical hardcode.

## What shipped

1. **Memory-budgeted launch (the fix).** New `LlamaServer::derive_ctx_batch(max_mem, repo_root)` (Rust) and
   `derive_ctx_batch(max_mem, repo_root)` (Python) map the memory budget to a KV-cache-safe pair:
   ≥16 GB → 8192/4096 · ≥8 GB → 8192/2048 · ≥4 GB → 4096/1024 · ≥2 GB → 2048/512 · else 1024/256.
   Default budget 2048 MB therefore yields **ctx 2048 / batch 512**. Explicit operator overrides
   `AINISH_RAG_CTX` / `AINISH_RAG_BATCH` take precedence; multi-worktree hosts scale the batch down.
   `ainish-rag status` now prints `Embed Provider: local llama (ctx=2048 batch=512)`.
2. **API embedding provider.** Config fields `embed_provider` / `embed_api_base` / `embed_api_key` /
   `embed_model` / `embed_dim` in `RagConfig` (env + `.agents/rag/embed-provider.json`).
   `EmbedClient::with_config()` routes every call site (all 8, previously raw `EmbedClient::new`) through the
   provider; `embed_batch` POSTs to `{base}/embeddings` with a Bearer key when API mode is active and skips the
   loopback DNS-rebinding/PSK path. `LlamaServer::ensure_running` and Python `start_server` **return early in API
   mode**, so no local llama process is spawned at all. Python parity via `with_api_provider` /
   `embed_client_from_config` / `read_embed_provider_cfg` / `embed_provider_active`.
3. **`ainish-coder --embed-config`** (new molecule `src/embed_config.sh`): `--provider api --api-base URL
   --model NAME [--dim N]`, `--provider local` to revert, `--status` to inspect. Writes non-secret
   `.agents/rag/embed-provider.json` only; the key is read in memory from `AINISH_EMBED_API_KEY` and never
   persisted (P2 compliance).

## Notes / gotchas

- `std::env::set_var` is `unsafe` in this Rust edition — the ctx/batch test wraps it in `unsafe {}`.
- Under `set -euo pipefail`, `sed` on a missing file returns 2 and aborts a bare `var="$(sed … | head)"`
  assignment; `embed_config_status` guards with `|| true`.
- `read_provider_cfg` must accept JSON **numbers** for `dim`, not just strings.
- API mode deliberately skips the loopback guard (remote endpoint) but still honours DP noise/budget accounting.
