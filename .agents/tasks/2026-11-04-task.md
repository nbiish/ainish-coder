## Follow-up: EGM and master-suggestion context boundary

# Design: EGM master-suggestion context

## Problem

The always-on contract names the optional TypeSafe skill directly, while the
Elephant/Goldfish workflow does not surface the latest master suggestions in its
bounded orientation packet. This makes optional decision tooling look mandatory
and weakens the intended no-memory Goldfish review boundary.

## Goals

- Remove the optional TypeSafe skill from the always-on contract.
- Make the latest scrubbed master-suggestion record an explicit Elephant input.
- Keep Goldfish stateless: no memory, suggestions, chat history, or implementation.
- Preserve TypeSafe discoverability through the on-demand skills index.

## Non-goals

- Do not remove or rename the `typesafe-jev` skill.
- Do not add a second memory store or a model-dependent orchestration path.
- Do not change the existing RAG transport order.

## Constraints and invariants

- Root `AGENTS.md` and `.agents/canonical/AGENTS.md` remain byte-identical.
- Context packets stay bounded and never include secrets, transcripts, or resolved memory.
- Master suggestions are advisory; they never authorize changes or override acceptance criteria.
- Goldfish receives only the design artifact and explicitly listed references.

## Proposed architecture

`AGENTS.md` points to `context-orchestration` for orientation and lifecycle.
`bin/context-packet.sh --mode elephant` emits the latest suggestions file as
bounded metadata and recent lines. `--mode goldfish` emits only the stateless
boundary. The optional `typesafe-jev` skill remains listed in the skills index
and is loaded only when its trigger matches.

## Interfaces and data

- `AGENTS.md`: always-on navigation and lifecycle contract.
- `.agents/skills/context-orchestration/SKILL.md`: EGM and master-suggestion procedure.
- `bin/context-packet.sh`: bounded packet modes.
- `.agents/suggestions/*-suggestions.txt`: scrubbed advisory input for Elephant mode.
- `.agents/skills/typesafe-jev/SKILL.md`: on-demand decision/image workflow.

## Files and symbols

- `AGENTS.md` and `.agents/canonical/AGENTS.md`
- `bin/context-packet.sh`
- `.agents/skills/context-orchestration/SKILL.md`
- `src/deploy_rules_sync.sh`

## Alternatives considered

Keeping the TypeSafe link in `AGENTS.md` would load an optional system for every
task. Loading all suggestions or memories into Goldfish would defeat the
stateless review firewall. A second orchestration manifest would duplicate the
existing `.agents/` contract.

## Risks and mitigations

Large suggestion ledgers could expand packets, so only the newest file and a
bounded tail are emitted. Stale or malformed suggestions remain advisory and
are not treated as authorization. Contract synchronization and packet smoke
tests catch drift.

## Implementation plan

1. Replace the always-on TypeSafe navigation entry with context orchestration.
2. Add bounded master-suggestion output to Elephant/build packets.
3. State the EGM boundary and on-demand skill rule in the workflow documentation.
4. Synchronize the canonical contract and verify byte identity.

## Verification and rollback

Run `bin/egm-check.sh --design` on this artifact, shell syntax checks, Elephant
and Goldfish packet smoke tests, canonical byte identity, and focused diff
validation. Roll back by reverting the single commit if packet boundaries or
contract synchronization fail.

## Open decisions

None; the TypeSafe skill remains available on demand only.
