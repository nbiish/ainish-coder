finding: seven other CLI flags carry the same latent clap defect that made `wiki --index` impossible to turn off — a `bool` field with `#[arg(long, default_value_t = true)]` is a flag that can ONLY ever be true.
evidence: in clap 4 a `bool` field with `long` is a presence flag (implicit `ArgAction::SetTrue`), so `default_value_t = true` makes the parsed value `true` whether or not the operator passes it — and there is no `--no-<flag>` counterpart. `ainish-rag wiki --index false` and `ainish-rag wiki --index=false` both fail with "unexpected argument 'false' found" / the value is ignored, i.e. embedding was unavoidable. Same shape survives at `src/rag/src/main.rs`: `monitor.once` (130), `cleanup.compact` (278), `cleanup.prune_worktrees` (284), `orient.inject` (296), `orient.task_conditioned` (302), `orient.include_symbols` (317, note it DOES carry `action = ArgAction::Set` and is therefore the one that works), `gate.verify` (410). The `wiki.index` instance was fixed here because it was blocking the retired-embedding path outright.
options: (a) for flags that should default ON and be disable-able, declare `#[arg(long, default_value_t = true, action = clap::ArgAction::Set)]` and accept `--flag true|false` (the pattern `include_symbols` already uses); (b) prefer `#[arg(long, action = clap::ArgAction::SetTrue)]` with an inverted name (`--no-inject`, `--no-once`) so the default is `false` in code and the flag is a real opt-out; (c) add a `try_parse` round-trip test per flag asserting both polarities parse to different values — that is the only check that distinguishes "declared" from "usable". (a) is the smallest change and matches existing precedent in the file.
scope: pre-existing, independent of the hour-stamp work. Recorded because the failure is silent: the help text says "(default: true)" and reads as configurable, while the flag silently cannot be set to false.
