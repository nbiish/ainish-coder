finding: six other RAG subcommands still carry the clap `default_value_t = true` defect that made `wiki --index` impossible to disable, and one of them (`orient`'s flags) is on the agent-facing path.
evidence: in clap 4 a `bool` field with `long` is a presence flag (implicit `ArgAction::SetTrue`), so `default_value_t = true` yields a flag that can only ever be true — there is no `--no-x`, and `--x false` is rejected as an unexpected argument. Measured live: `ainish-rag wiki --index false` failed with "unexpected argument 'false' found". The `wiki.index` instance was fixed in this task by removing the default. Remaining instances in `src/rag/src/main.rs`: `orient.inject`, `orient.task_conditioned`, `cleanup.compact`, `cleanup.prune_worktrees`, `gate.verify`, `monitor.once`. Only `orient.include_symbols` is genuinely configurable because it alone carries `action = clap::ArgAction::Set`.
options: (a) for flags that should default ON and be disable-able, add `action = clap::ArgAction::Set` and accept `--flag true|false`, the pattern `include_symbols` already uses; (b) prefer `SetTrue` with an inverted name (`--no-inject`) so the default is false in code and the flag is a real opt-out; (c) add a per-flag `try_parse` round-trip test asserting both polarities differ — the only check that distinguishes "declared" from "usable". (a) is smallest and matches existing precedent.
scope: pre-existing; independent of the EGM/vector work. `orient.inject` matters most: its help says "(default: true)" and reads as configurable while `--inject false` cannot be expressed, so an agent trying to disable injection silently gets it anyway.
