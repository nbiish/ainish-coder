# Suggestions — federation after `--machine-link`

Ordered by what would bite first.

1. **`goal-first-trillion` is three repositories, not one repo out of date.** Root commits `026b902`
   (Mac), `207d89e` (Windows), `39005a8` (origin) share no ancestor; only 3 paths are common and all 3
   differ in content. Origin is newest (45 commits / 132 files), the Mac holds `analysis/income-ledger.md`
   and `orchestration/crew-roster.md`, Windows holds `src/*.ts` (the Gumroad API). Both Mac tips are now
   preserved as `preserve/mac-3c87fac` and `preserve/mac-dirty-tree` and were delivered to the peer, but
   the actual convergence is a manual merge against `origin/main`. Nothing in `--machine-sync` can make
   unrelated histories fast-forward, and pretending otherwise is how a fleet believes it is synced while
   running two different projects.

2. **Windows' `machines.txt` still points the Mac peer at the wrong root.** It maps
   `mac-18gb=mac-18gb:/Users/nbiish/code`, so a sync started on Windows looks for
   `/Users/nbiish/code/goal-first-trillion`, which does not exist — the Mac copy lives under
   a removable-volume code root on this Mac. `--machine-link` on the Windows side fixes this per repo; a
   corrected code root in the registry fixes it for every repo at once.

3. **A hook that fires on every commit needs a debounce story.** `--machine-link` sends on
   `post-commit` and `post-merge`, which is right for how this operator works, but a rebase or a
   `git commit --amend` loop will push repeatedly. It is bounded (`ConnectTimeout`, `|| true`) and
   cannot block a commit, but a repo with many small commits will spend real time in ssh. If that
   becomes annoying, the fix is a minimum interval stamp in `.git/ainish-machine-sync.stamp` rather
   than dropping the hook.

4. **`_ms_remote` now runs `bash -c` for local peers.** That is what makes a local-peer sync work at
   all, and it matches what an ssh peer sees. The edge it does not cover is a local Windows checkout
   addressed as a plain path rather than through WSL — `bash -c` will not exist there. Today the
   registry expresses that case as an ssh peer or a POSIX path, so this is theoretical, but it is the
   assumption to re-check if local Windows peers ever appear.

5. **`--machine-sync --all` is sequential by design.** Each repo runs its own sync in the calling
   shell, so a slow peer serialises every repo behind it. Parallelising would be faster and would also
   make interleaved output unreadable; if it is wanted, have each repo write its own log and print a
   summary.
