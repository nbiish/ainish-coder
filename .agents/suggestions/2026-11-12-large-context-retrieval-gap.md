evidence: `retrieve_context` now returns `{"hits": [], "mode": "wiki_graph_empty", "notice": "no wiki/.agents artifact covers this task; read the files directly."}` with no fallback, by operator decision (the vector path was deleted rather than kept as a fallback). The operator's stated direction is "expert database calls with modern one million context models" — that capability is exactly what the deleted fallback was standing in for, so the natural replacement is not another index but letting a large-context model read the relevant files directly.
options: (a) add a `--context --deep` mode that, on a graph miss, hands the *file list* (not chunks) to a 1M-context driver call and asks which files to read — an LLM-directed file selection rather than an embedding-retrieved chunk set; (b) have `wiki_graph_empty` name the three or four most likely directories from the task terms so the agent's own read is directed rather than cold; (c) leave it: the notice already tells the agent to read files, and the agent has tools to do so. (a) is the version that matches the stated direction and costs one model call where the deleted path cost a model download plus an index build. (b) is nearly free.
