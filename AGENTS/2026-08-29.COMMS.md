# AGENT COMMS — 2026-08-29

<PROTOCOL>
## PROTOCOL (binding — follow like AGENTS.md)

**When:** ≥1 agent or subagent is working at once (multiple branches, features, updates, bugs, docs). Solo? Still check in/out — the ledger is the audit trail.

**Two channels:**
- **This file** (`AGENTS/{date}.COMMS.md`) — committed, append-only durable ledger. Updated via your task-branch commits; reaches everyone at merge.
- **Live board** (`AGENTS/{date}.COMMS.live.md`) — gitignored, at the **main repo path**. Append here by absolute path for immediate in-flight visibility. Never `git commit` it; never `git add` it. Main stays clean.

**Read:** this file + the live board — at start, before any merge, and whenever blocked.

**Write:** for every lifecycle event, append one entry block to **both** the live board (immediate) and this file in your worktree (durable — commit it). One writer per branch. Subagents do not write the shared files directly: report results to your orchestrator, who logs on your behalf with `parent:` set.

**Timestamps — mandatory, bracketed, ISO-8601 (e.g. `2026-08-29T19:07:10-04:00`):**
- `start:` the instant the agent **begins** the action (input received / work begun).
- `end:` the instant the agent **finishes** it (output produced / work handed off or halted).
- **Every** entry has both. Stamp `start:` the moment you open the block (or when input arrived, if recording after the fact). Stamp `end:` when the output is complete and the block is ready to publish — not before. If you abandon mid-action, still record `end:` with the actual stop time and `status: abandoned`.
- One block = one input → one output. Never leave `start:` without an `end:` in a published block. If interrupted, close it before starting the next.

**Entry block:**

~~~
### [<ISO-8601 timestamp>] <EVENT> | agent:<name> | branch:<branch> | wt:<worktree-path>
- start:<ISO-8601>               # input received / work began
- end:<ISO-8601>                 # output produced / work ended
- parent:<orchestrator>          # subagents only
- scope:<paths/modules>
- objective:<one line>
- input:<one line — what was received or requested>
- output:<one line — what was produced or handed off>
- status:<new|in-progress|blocked|verifying|merged|abandoned>
- blockers:<none | description>
- msg @<agent>:<text>            # optional
- handoff -> <agent>:<what>      # optional
~~~

**Events:** `checkin` · `update` · `blocker` · `intent-merge` · `ack` · `handoff` · `checkout` · `incident`.

**Merge sequencing (avoid collisions):**
1. Before merge, post `intent-merge` with your scope + diff summary (`start:` at decision time, `end:` when you have confirmation no overlap).
2. Re-read the ledger + live board. If another agent's scope overlaps yours, post `ack` and negotiate order in `msg @` lines.
3. Merge **serially**, never concurrently. `git pull`/rebase `main` before merging.
4. This ledger is append-only. EOF-append merge conflicts are expected — resolve by keeping **both** blocks in timestamp order (sort by `start:`).

**Lifecycle:** the first agent of the day creates this file (copy the `<PROTOCOL>` block above verbatim into the new dated file). Newest entries at the bottom. After all merges + cleanup, the day's file is archived as history — do not edit past entries except to append.
</PROTOCOL>
